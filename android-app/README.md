# Android app (Capacitor)

A sideloadable APK, named "My Father's Work (Unofficial)" on the phone: the published Blazor app inside a Capacitor 8 WebView.
The narration clips (~400 MB) are **not** in the APK; players download them in the app (Offline play) from the
website, and a clip that is not downloaded streams from there.

| | In the APK | Downloaded in the app (Offline play) |
|---|---|---|
| App, images, localization, music, sound effects | yes | |
| Narration clip lists (`<Scenario>.json`) and pause lists | yes | |
| `audio/vo/packs.json` (what each download contains, made from this build's clips) | yes | |
| Oliver narration, per scenario (~110-140 MB each) | | yes, ticked by default on first start |
| Original male / female voice (~20 MB each) | | yes, unticked by default |

## How it works

- `tools/android-stage.py` fills `android-app/www` (Capacitor's `webDir`) from `dotnet publish` output: base href stays
  `/`, the `.mp3` files under `audio/vo` are left out (after `audio-packs.py` listed them), `js/edition.js` says
  `native: true` and `remote: "https://vdepagter.github.io/myfathersworkapp/"`, no service worker, and `js/capacitor.js`
  + `web/native.js` (Back button) are added to `index.html`.
- `js/audio-cache.js` downloads from `remote` but stores each clip under the app's own url (`https://localhost/...`), in
  the same `mfw-audio` cache as the website. `js/audio.js` plays a stored clip from a `blob:` url and streams any other
  clip from `remote`. `js/offline.js` treats the app as installed and always available offline (Offline play shows only
  the narration downloads; it opens by itself on the first start). GitHub Pages sends `Access-Control-Allow-Origin: *`.
- `capacitor.config.json`: **never change `androidScheme` (https), `hostname` (localhost) or `appId`.** The saves, the
  Endings Gallery and the downloaded narration belong to that origin and package.
- Back button (`web/native.js`): closes an open panel; in a game it opens (and closes) the pause menu; elsewhere it goes
  back a page; on the Main Menu the app goes to the background.
- Version: `versionName` 0.66.6.&lt;revision&gt;, `versionCode` &lt;revision&gt; (`-PmfwRevision`, same revision as the website),
  so every build installs over the previous one and the downloads stay.

## Signing

One release keystore, kept outside the repository (owner's laptop: `%USERPROFILE%\keys\myfathersworkapp-release.jks`,
password file next to it; copies in the owner's Dropbox `Documents\Administratie\Certificaten`). An APK signed with
another key cannot update an installed app: players would have to export their saves (Saved Games) and Endings Gallery,
uninstall, install the new build, import them again and download the narration again. Never hand out a debug-signed
build.
`android-app/set-secrets.ps1` stores it as the repository secrets `ANDROID_KEYSTORE_BASE64`,
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.

## Build

GitHub: Actions > **Android APK** > Run workflow (artifact `MyFathersWork-Unofficial-<version>-android`), or push a tag
`v*` to attach the APK to that release.

Locally (Node 22+, JDK 21, Android SDK with platform 36; set `JAVA_HOME` and `ANDROID_HOME`):

```powershell
dotnet publish MyFathersWorkApp/MyFathersWorkApp/MyFathersWorkApp.csproj -c Release -o <empty dir>
npm ci --prefix android-app
python tools/android-stage.py <dir>/wwwroot
cd android-app; npx cap sync android; cd android
$env:ANDROID_KEYSTORE_FILE = "$env:USERPROFILE\keys\myfathersworkapp-release.jks"   # + the three password/alias variables
./gradlew assembleRelease -PmfwRevision=<revision>
```

The APK is `android-app/android/app/build/outputs/apk/release/app-release.apk`. Test on an emulator started with
`-no-audio`; inspect the WebView at `chrome://inspect` (Edge: `edge://inspect`).

`android/` is generated by `npx cap add android` and committed with these changes: `app/build.gradle` (version,
signing), launcher icons and splash images (from `wwwroot/icon-512.png`), `ic_launcher_background` #111111.

## Google Play

Play takes an App Bundle: the **Android APK** workflow also builds `MyFathersWork-Unofficial-<version>.aab`, signed with
the same release key (artifact `MyFathersWork-Unofficial-<version>-android`). The `.aab` is for Play only and is not
attached to GitHub Releases.

**Play App Signing must use our release key**, never a key that Google generates: otherwise the Play version could not
update a sideloaded install and the other way round. Before the first release, in Play Console: Test and release >
App integrity > Play app signing > "Use a different key" > "Export and upload a key from Java keystore", download
`pepk.jar` and the encryption public key into one folder, run `pwsh android-app/play-signing.ps1 -Folder <folder>`
and upload the `output.zip` it writes. The upload key can be the same key.

New personal developer accounts must run a closed test with at least 12 testers for 14 days before applying for
production. Listing graphics: `docs/store/play/` (icon 512×512, feature graphic 1024×500, phone screenshots 1080×1920).
